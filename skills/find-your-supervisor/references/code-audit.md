# Code archaeology protocol

A paper's repository is not an implementation guarantee. Treat code review as a scientific audit.

## Reproducible source anchoring

Record canonical repository URL, whether official, license, exact commit SHA / tag, default branch at audit time, dependencies/submodules, external checkpoints and source files. A GitHub README has its own review status; it does not count as inspected code. Note code release year may differ from paper version.

## Trace actual computation

1. **Repository triage:** entrypoints, configuration(s), model registry, dataset readers/preprocessing, CUDA ops, train loop, validation/postprocessing, logging/checkpoints.
2. **Dataflow:** write a small, exact graph `raw input → preprocessing → backbone → proposed module → losses → decoded predictions → evaluator`. Record shapes, coordinate conventions, units, random seeds, detach/freeze locations and places where ground truth may leak.
3. **Claim-to-source map:** link each contribution/equation/figure to file path, function/class and relevant line range (anchored to pinned commit, not only floating `main`). Flag missing or inconsistent paper-to-code semantics.
4. **Training and inference separately:** identify branches, teacher-only inputs, causal masks, cache updates, teacher forcing, batch vs streaming forward; measure requested resources separately.
5. **Red flags:** undocumented preprocessing, precomputed oracle labels, undocumented test-time augmentation, different baselines/data, hard-coded device, stale dependencies, license incompatibilities, missing weights or evaluation scripts.
6. **Coverage:** document the set of first-party and academically relevant source files, exclusions (vendored code, autogenerated docs), inspected files with explicit evidence and a centrality ranking. Reviewing 5 core files is a useful `core_partial` milestone, not `complete_code_audit`.

## Safe experimentation

Never execute untrusted install instructions, curl|bash or arbitrary third-party Python without inspecting it and obtaining an authorized sandbox. Pin dependencies, isolate package installation and avoid sending private credentials/data. For binary extensions, read build scripts and document architecture requirements.

## Deliverable

Build a table `paper_claim / source_file@SHA:function / observed implementation / confidence / discrepancy / suggested ablation` plus a minimal reproduction recipe. If unavailable, mark `blocked`, not `done`.
